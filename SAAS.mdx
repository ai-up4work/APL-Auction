# Valiant League SaaS Implementation

Complete enterprise-grade SaaS transformation of the Valiant League application with multi-tenant architecture, comprehensive authentication, role-based authorization, and advanced tournament management systems.

---

## 🏗️ Architecture Overview

The Valiant League SaaS is built on a **multi-tenant, organization-first** architecture using Supabase as the backend database. The application supports auctions (cricket player bidding), tournaments (bracket-based competitions), and real-time match tracking with comprehensive analytics.

### Core Design Principles

- **Multi-Tenant Isolation**: Complete data isolation between organizations
- **Role-Based Access Control (RBAC)**: Three-tier permission model (Admin, Manager, Viewer)
- **Real-time Capabilities**: WebSocket support for live auctions and matches
- **Scalable Architecture**: Horizontal scaling via serverless functions and databases
- **Type Safety**: Full TypeScript implementation with strict type checking
- **Security First**: RLS policies, input validation, and secure session management

### Core Tables Details

#### Organizations (`organizations`)

Primary container for all multi-tenant data.

```sql
CREATE TABLE organizations (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name text NOT NULL,
  slug text NOT NULL UNIQUE,
  description text,
  logo_url text,
  created_by uuid NOT NULL REFERENCES auth.users(id),
  plan text NOT NULL DEFAULT 'free', -- free, pro, enterprise
  status text NOT NULL DEFAULT 'active', -- active, suspended, deleted
  created_at timestamp DEFAULT now(),
  updated_at timestamp DEFAULT now()
);
```

**Purpose**: Contains organization metadata and billing information.

**Key Features**:
- `slug`: URL-friendly identifier for organization URLs
- `plan`: Subscription tier affecting feature availability
- `status`: Soft delete support via status field
- Audit timestamps for tracking changes

#### User Profiles (`user_profiles`)

Extended user information linked to Supabase Auth.

```sql
CREATE TABLE user_profiles (

  full_name text,
```

#### Organization Memberships (`org_memberships`)

Maps users to organizations with role-based access.

```sql
CREATE TABLE org_memberships (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id uuid NOT NULL REFERENCES organizations(id),
  user_id uuid NOT NULL REFERENCES auth.users(id),
```

**Purpose**: Join table enabling users to belong to multiple organizations with different roles.

**Key Features**:
- `role`: Controls permission level (hierarchical: viewer < manager < admin)

### Auction Database Operations

**Creating an Auction:**
```typescript
const auction = await supabase
  .from('auctions')
  .insert({
    name: 'APL Season 1',
    org_id: currentOrgId,
    created_by: userId,

```

**Adding Players:**
```typescript

  .from('players')
  .insert([
    {
      auction_id: auctionId,
      name: 'Player Name',
      role: 'Batter',
      origin: 'Local',
      price: 500,
      country: 'USA'
    }
  ])
  .select();
```

**Creating Teams:**
```typescript
const team = await supabase
  .from('teams')
  .insert({
    auction_id: auctionId,
    code: 'TEAM_A',
    name: 'Team A',
    owner: 'Owner Name',
    tier: 'Pro',
    remaining_purse: 50000
  })
  .single();
```

**Recording Bids:**
```typescript
// 1. Create lot (player becomes available)
const lot = await supabase
  .from('auction_lots')
  .insert({
    auction_id: auctionId,
    player_id: playerId,
    lot_number: 1,
    base_price: 500,
    status: 'pending'
  })
  .single();

// 2. Record bids
const bid = await supabase
  .from('bid_history')
  .insert({
    lot_id: lotId,
    team_id: teamId,
    amount: bidAmount,
    auction_id: auctionId
  });

// 3. Update lot with highest bid
await supabase
  .from('auction_lots')
  .update({ current_bid: bidAmount })
  .eq('id', lotId);
```

**Completing Auction:**
```typescript
// Mark player as sold
await supabase
  .from('players')
  .update({
    status: 'sold',
    sold_to_team_id: winningTeamId,
    sold_price: finalBid
  })
  .eq('id', playerId);

// Close lot
await supabase
  .from('auction_lots')
  .update({
    status: 'sold',
    winning_team_id: winningTeamId,
    closed_at: new Date()
  })
  .eq('id', lotId);
```

```typescript
function calculateStandings(matches) {
  const standings = {};
  
  matches.forEach(match => {
    if (!standings[match.winner_id]) {
      standings[match.winner_id] = {
        played: 0,
        won: 0,
        lost: 0,
        points: 0
      };
    }
    
    standings[match.winner_id].won++;
    standings[match.winner_id].points += 2;
    standings[match.winner_id].played++;
    
    // Similar for loser
  });
  
  return Object.entries(standings)
    .sort((a, b) => b[1].points - a[1].points);
}
```

## 🔐 Row-Level Security (RLS)

All tables implement RLS policies to ensure data isolation:

### Auction Policies

```sql
-- Users can only see auctions in their organizations
CREATE POLICY "Users can view org auctions"
  ON auctions FOR SELECT
  USING (org_id IN (
    SELECT org_id FROM org_memberships WHERE user_id = auth.uid()
  ));

-- Only managers+ can create auctions
CREATE POLICY "Managers can create auctions"
  ON auctions FOR INSERT
  WITH CHECK (
    org_id IN (
      SELECT org_id FROM org_memberships 
      WHERE user_id = auth.uid() AND role IN ('manager', 'admin')
    )
  );
```

### Tournament Policies

```sql
-- Users can only manage tournaments in their orgs
CREATE POLICY "Users can view org tournaments"
  ON tournaments FOR SELECT
  USING (org_id IN (
    SELECT org_id FROM org_memberships WHERE user_id = auth.uid()
  ));
```

## 🛡️ Security Features

### Input Validation

```typescript
const schema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
  fullName: z.string().min(2)
```

### SQL Injection Prevention

Supabase automatically uses parameterized queries:
```typescript
// ✅ Safe - parameterized
await supabase
  .from('teams')
  .select()
  .eq('name', userInput);

// ❌ Dangerous - string concatenation
const query = `SELECT * FROM teams WHERE name = '${userInput}'`;
```

- SameSite=Strict prevents CSRF
- Secure flag ensures HTTPS only

## 🚀 Performance Optimizations

### Database Indexes

All frequently queried columns are indexed:
```sql
CREATE INDEX idx_org_memberships_user_id ON org_memberships(user_id);
CREATE INDEX idx_auctions_org_id ON auctions(org_id);
CREATE INDEX idx_tournament_org_id ON tournaments(org_id);
CREATE INDEX idx_bid_history_lot_id ON bid_history(lot_id);
```

### Denormalization Strategy

Team data in `bid_history` for fast queries:
```sql
-- Instead of joining teams table
SELECT 
  bh.amount,
  bh.team_name,  -- Denormalized
  bh.team_color  -- Denormalized
FROM bid_history bh
WHERE bh.lot_id = $1
ORDER BY bh.placed_at DESC;
```

### Query Optimization

```typescript
// ✅ Efficient - single query
const auction = await supabase
  .from('auctions')
  .select(`
    *,
    teams(*),
    auction_lots(*, bid_history(*))
  `)
  .eq('id', auctionId)
  .single();

// ❌ Inefficient - N+1 queries
const auction = await supabase.from('auctions').select().single();
for (const lot of auction.lots) {
  const bids = await supabase.from('bid_history').select().eq('lot_id', lot.id);
}
```

### Caching Strategy

```typescript
// Cache organization data for 5 minutes
const orgs = await cache(
  () => getOrgMembers(orgId),
  { revalidate: 300 }
);
```

## 🔄 Real-time Updates

### Supabase Realtime

```typescript
// Listen for bid changes
const subscription = supabase
  .channel(`auction:${auctionId}`)
  .on(
    'postgres_changes',
    {
      event: 'INSERT',
      schema: 'public',
      table: 'bid_history',
      filter: `lot_id=eq.${lotId}`
    },
    (payload) => {
      console.log('New bid:', payload.new);
      updateBidUI(payload.new);
    }
  )
  .subscribe();

return () => supabase.removeChannel(subscription);
```
